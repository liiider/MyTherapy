# MyTherapy 信息架构

## 1. 文档目的

本文件用于定义 MyTherapy MVP 的信息架构，明确一级导航、二级页面、页面职责和模块边界。

本文件优先服务于：

- 产品范围收敛
- 原型设计
- 页面清单确认
- 后续开发拆分

## 2. 架构原则

MVP 的信息架构遵循以下原则：

- 高频动作优先
- 首页围绕今天的任务
- AI OCR 导入是第一入口，不是隐藏能力
- 低频配置集中收纳，避免打扰主路径
- 信息架构先为 iOS MVP 服务，再考虑小程序裁剪

## 3. 一级导航建议

MVP 建议使用 4 个底部导航：

1. 今日
2. 记录
3. 我的疗程
4. 设置

说明：

- “今日”负责执行
- “记录”负责回顾和趋势
- “我的疗程”负责管理治疗对象
- “设置”负责权限、账户、帮助和偏好

不建议首版单独保留“支持”一级导航。

原因：

- MVP 功能尚少，单独占一个底部 Tab 成本较高
- 帮助和反馈可先并入设置
- 底部导航控制在 4 个更稳定

## 4. 一级导航详情

### 4.1 今日

定位：

- 用户每天打开次数最多的主页面
- 负责“今天该做什么”

建议包含模块：

- 顶部状态区
- 横向日期条
- 下一次服药卡片
- 今日待完成任务
- 已完成任务折叠区
- 风险提醒区
- 悬浮新增按钮

二级页面：

- 月历弹层
- 任务详情页
- 用药执行确认页
- 快速新增菜单

### 4.2 记录

定位：

- 回顾执行情况
- 查看趋势和历史记录

建议包含模块：

- 概览视图
- 历史列表视图
- 连续完成天数
- 完成率摘要
- 副作用摘要
- 指标摘要

二级页面：

- 历史记录详情页
- 副作用详情页
- 指标详情页
- 导出页

### 4.3 我的疗程

定位：

- 管理当前治疗计划中的对象
- 维护药物、指标和症状结构

建议包含模块：

- 药物分组
- 指标分组
- 副作用 / 症状分组
- 预约 / 任务分组

二级页面：

- 药物详情页
- 药物编辑页
- 指标项目页
- 副作用项目页
- 新增对象菜单

### 4.4 设置

定位：

- 处理系统设置、权限、账户和帮助

建议包含模块：

- 个人资料
- 提醒与通知设置
- 权限状态
- 帮助与反馈
- 数据与备份
- 关于产品

二级页面：

- 通知设置页
- 权限检查页
- 帮助中心
- 常见问题
- 反馈入口

## 5. AI OCR 在架构中的位置

AI OCR 不是一个深层工具，而是核心能力。

建议放置位置：

- 首次空状态主按钮
- 今日页悬浮新增按钮第一项
- 我的疗程页新增入口第一项

OCR 相关页面链路：

1. 导入来源选择
2. 拍照 / 上传
3. OCR 处理中
4. OCR 结果确认
5. 服药计划生成
6. 成功返回今日页

## 6. 页面层级建议

### 6.1 P0 页面

必须在 MVP 中设计和实现：

- 今日页
- 月历弹层
- OCR 导入页
- OCR 结果确认页
- 任务详情页
- 服药记录动作页
- 记录页概览
- 记录页列表
- 导出页
- 我的疗程页
- 药物详情页
- 药物编辑页
- 设置页
- 通知与权限页

### 6.2 P1 页面

可在 MVP 后扩展：

- 日历接入页
- 家属协助页
- 帮助聊天页
- 多护理对象页
- 旅行备药页

## 7. 首页信息优先级

首页信息从上到下建议按以下优先级排列：

1. 今天 / 日期上下文
2. 下一次服药
3. 今日待完成任务
4. 已完成任务
5. 库存风险
6. 副作用或指标提醒

不建议首页首屏放：

- 过多统计图
- 大段教育内容
- 广告
- 非当天相关的扩展工具

## 8. 记录页信息优先级

记录页建议分为两个页签：

- 概览
- 历史

概览优先展示：

- 本周完成率
- 连续完成天数
- 最近副作用
- 最近指标记录

历史优先展示：

- 按日期分组的服药记录
- 每条记录的计划时间与实际时间
- 跳过与延后状态

## 9. 我的疗程页信息优先级

建议默认按 Section 分组：

- 药物
- 指标
- 副作用 / 症状
- 预约

药物卡片建议包含：

- 药名
- 服药频次
- 下次时间
- 剩余库存

## 10. 设置页信息优先级

建议顺序：

1. 个人资料
2. 通知与提醒
3. 权限状态
4. 数据与备份
5. 帮助与反馈
6. 关于

原因：

- 对提醒类产品来说，通知和权限的重要性远高于一般设置项
- 这些内容应前置，而不是埋深

## 11. 小程序裁剪建议

如果后续推出微信小程序，建议裁剪为：

保留：

- 今日
- 简化记录
- 导入入口
- 数据导出

弱化或延后：

- 深度提醒依赖
- 复杂配置项
- 复杂趋势分析

## 12. 结论

MVP 的最佳信息架构不是“大而全”，而是围绕患者的日常执行闭环。

因此，MyTherapy 的信息架构应以“今日”为核心，以“记录”和“我的疗程”为支撑，以“设置”承接权限和帮助。
