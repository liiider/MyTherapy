# MyTherapy 交接文档 - 2026-04-27

## 1. 今日目标

按 iOS App Store 上架方向继续开发，同时保持“前端本地优先、后端尽量小”的架构：

- App 形态回归到移动端应用，不继续把主体验做成 Web 管理后台。
- 前端负责大部分数据、交互、任务生成、记录和报告。
- 后端只承担 AI/OCR API 中转、未来账号与付费用户权益管理。
- 避免硬编码密钥，智谱 API key 只能通过环境变量注入。

## 2. 今日完成

### 2.2 轻后端与智谱 API 接入

- 新增 `server/aiService.js`，统一封装 AI/OCR 服务。
- 支持环境变量：
  - `ZHIPUAI_API_KEY`
  - `BIGMODEL_API_KEY`
  - `ZHIPU_TEXT_MODEL`
  - `ZHIPU_VISION_MODEL`
  - `ZHIPU_BASE_URL`
  - `ZHIPU_TIMEOUT_MS`
- 未配置 API key 时自动使用本地 mock，保证开发和测试可离线运行。
- 后端保持轻量：当前仍是 Node 内置 HTTP 服务和 JSON 文件存储。
- `server/store.js` 支持 `MYTHERAPY_DATA_DIR`，测试时可隔离数据目录。

### 2.4 App Store 风险收敛

- 移动端用户可见文案收敛为“用药计划 / 提醒 / 记录”。
- 避免把产品表达成诊断、治疗、处方或剂量建议工具。
- AI 口径保持为“结构化整理”，不做医疗判断。
- AI 生成内容保存前需要用户确认隐私授权。

### 2.5 验证脚本

## 7. 交接注意

- 不要把用户提供的真实 API key 写入任何文件。
- 智谱 key 只通过环境变量配置。
- AI 输出必须保持“整理和结构化”边界。
- 药品、剂量、频次、疗程相关字段必须由用户人工确认后生效。
- 上架前不要引入“诊断、治疗建议、推荐剂量、替代医生”等高风险文案。
