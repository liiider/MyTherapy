# MyTherapy 竞品截图参考分析

## 1. 目的

本文件用于记录对参考产品截图的拆解结论，方便后续在产品设计、交互设计、信息架构和工程实现中作为参考依据。

本次参考对象主要是一款患者侧用药管理 App 的实际页面截图。分析重点不是照搬，而是提取其中已经被验证过的产品结构、关键交互和实现思路。

## 2. 整体判断

从截图来看，这款产品的核心不是“复杂医疗系统”，而是“围绕患者日常执行”的轻量治疗管理工具。

它的优势在于：

- 首页非常聚焦当天任务
- 导航非常稳定，核心模块边界清晰
- 多数页面信息密度不高，降低了医疗产品的压迫感
- 功能上围绕“提醒、执行、记录、复盘、支持”形成闭环
- 很多扩展能力不是主流程，但被放进了容易发现、又不打扰主任务的位置

## 3. 业务结构拆解

从截图可推断出的核心业务结构如下：

### 3.1 今日

主要承担：

- 展示今天的待执行任务
- 按日期切换查看每日任务
- 展示已完成任务
- 提供快速添加入口

这是整个产品最核心的使用页面，也是用户每天最可能打开的页面。

### 3.2 进展

主要承担：

- 展示连续执行情况
- 展示图表或列表形式的服药表现
- 承接与健康平台连接
- 承接一些衍生工具，例如旅行计划器

这是“回顾与复盘”页面，不是主执行页。

### 3.3 支持

主要承担：

- 提供客服或产品助手入口
- 提供添加约会、医生、药房等辅助入口

这个模块承担的是支持能力，而不是核心业务流。

### 3.4 我的疗程

主要承担：

- 管理药物、测量、活动、情绪与症状等对象
- 通过分组方式管理治疗内容
- 提供新增入口和治疗结构编辑能力

这个页面更像“治疗配置中心”。

### 3.5 设置 / 护理对象

主要承担：

- 账户资料
- 提醒设置
- 通知类别
- 偏好设置
- 护理对象切换

这是产品配置层，不直接参与主路径。

## 4. 页面流和功能关系

从截图可以整理出较完整的业务流：

1. 用户进入“今日”
2. 查看当天任务
3. 执行某一项服药或提醒任务
4. 在“今日”或“进展”中查看完成情况
5. 在“我的疗程”中维护药物或测量项目
6. 在“设置”中处理提醒权限、个人资料和护理对象
7. 在“支持”中获得帮助或管理外围资源

这说明它把产品分成了两类动作：

- 高频动作：今日执行、快速记录
- 低频动作：配置、维护、支持、扩展工具

这个分层是值得直接借鉴的。

## 5. 视觉和交互风格

### 5.1 风格关键词

- 温和
- 轻医疗感
- 非医院化
- 低压、低干扰
- 偏生活方式产品，而不是重临床系统

### 5.2 视觉特征

- 大面积浅色背景
- 非纯白，带一点暖色倾向
- 卡片圆角较大
- CTA 使用浅粉橘色
- 图标和插画偏柔和
- 留白很多，信息密度偏低
- 底部导航稳定且长期可见

### 5.3 可借鉴点

- 用温暖而不是冰冷的方式做健康产品
- 主页面避免堆积过多统计信息
- 插画只用于解释或缓和页面气氛，不抢功能层级
- 关键任务列表保持极简

## 6. 截图中最值得借鉴的优势点

### 6.1 首页围绕“今天”

优势：

- 用户打开应用时不需要重新理解界面
- 今天该做什么一目了然
- 任务完成后能立即获得反馈

可借鉴实现：

- 我们的首页也应该优先是“今天的药”和“下一次服药”
- 不要让首页先变成复杂的数据看板

### 6.2 日期条非常适合连续习惯产品

截图里的横向日期条是一个很强的行为引导。

优势：

- 让用户自然聚焦具体哪一天
- 降低日历的复杂度
- 让连续行为有节奏感

可借鉴实现：

- 首页保留横向日期条
- 点击日期切换当天计划
- 再用底部弹出月历完成全局日期跳转

### 6.3 月历使用底部弹层，而不是整页跳转

优势：

- 用户不会离开“今日”主场景太远
- 上下文保持稳定
- 查某一天记录的成本低

可借鉴实现：

- 我们可以采用半屏 Bottom Sheet 月历
- 月历只承担日期选择，不承担复杂分析

### 6.4 已完成任务单独折叠

优势：

- 减少视觉噪音
- 让未完成任务更突出
- 又保留可追溯性

可借鉴实现：

- 首页任务区建议拆成：
- 待完成
- 已完成（默认折叠）

### 6.5 “添加”按钮始终固定在右下角

优势：

- 用户永远知道从哪里新增
- 适合这种对象较多的治疗管理产品

可借鉴实现：

- 我们也可以保留统一新增入口
- 但新增菜单的第一项应该是“拍照导入医嘱/处方”
- 这会更符合我们的 AI OCR 核心卖点

### 6.6 进展页同时支持图表和列表

优势：

- 图表适合“趋势感知”
- 列表适合“精确回看”
- 同一个模块满足不同用户需求

可借鉴实现：

- 我们后续也应考虑：
- 概览视图
- 记录视图

但 MVP 阶段不必做太重图表。

### 6.7 “我的疗程”按对象类型分组

截图中按药物、测量、活动、情绪和症状分组，很适合长期治疗管理。

优势：

- 信息组织清楚
- 扩展新类型容易
- 用户知道去哪里修改具体内容

可借鉴实现：

- 我们也建议按对象类别分组管理：
- 药物
- 指标
- 副作用 / 症状
- 预约或任务

### 6.8 权限异常有明显提醒条

截图里明显提示“提醒可能不起作用”。

优势：

- 医疗类提醒产品最怕“用户以为会提醒，结果没有”
- 权限风险被前置暴露

可借鉴实现：

- 我们必须把通知权限、系统限制、电池设置等异常状态前置展示
- 这应当是 MVP 级别需求，不是以后再做

### 6.9 支持页和聊天助手独立存在

优势：

- 让帮助入口清晰
- 避免把帮助混在设置里太深

可借鉴实现：

- 我们未来也可以保留“帮助与支持”模块
- 但 MVP 不建议先做成复杂聊天助手
- 可以先做常见问题和反馈入口

### 6.10 护理对象机制

截图展示了“添加护理对象”和头像系统。

优势：

- 适合家属协助场景
- 适合一个账户管理多位被照护对象

对我们的判断：

- 这是有价值的扩展方向
- 但不适合首版 MVP

## 7. 从截图推断的实现方式

以下是较可能的实现思路，供后续设计和开发参考。

### 7.1 首页日期条

可能实现：

- 横向可滚动日期列表
- 当前选中日高亮
- 选中后刷新当天任务

技术实现：

- `FlatList` / 横向滚动列表
- 或 `uni-app` 横向 `scroll-view`

### 7.2 月历弹层

可能实现：

- Bottom Sheet
- 内部嵌一个月历组件

技术实现：

- iOS 原生风格底部抽屉
- React Native / uni-app 中都可通过弹层组件实现

### 7.3 今日任务卡片

可能实现：

- 按时间排序的任务列表
- 每条任务显示时间、对象、状态
- 右侧用勾选状态表示完成

技术实现：

- 本质是一个按日期过滤的任务数组
- 完成状态更新后即时局部刷新

### 7.4 已完成任务折叠区

可能实现：

- Accordion / Collapse
- 默认折叠，仅在用户需要时展开

### 7.5 右下角浮动新增按钮

可能实现：

- 固定悬浮按钮
- 点击后弹出 Action Sheet 或底部菜单

对于我们：

- 菜单项建议优先放：
- 拍照导入医嘱
- 手动添加药物
- 添加指标记录
- 添加副作用记录

### 7.6 “我的疗程”分组管理

可能实现：

- Section List
- 每个分组可折叠
- 每个对象卡片支持查看详情和编辑

### 7.7 进展图表

可能实现：

- 简单柱状图 / 打卡点阵 / 连续天数徽章
- 不一定需要复杂 BI 风格图表

这点很重要：

- 医疗执行类产品更适合“完成感”图表，而不是炫技图表

## 8. 我们应该借鉴但不能照搬的点

### 8.1 可以借鉴

- 首页“今天优先”
- 横向日期条 + 月历弹层
- 已完成任务折叠
- 固定新增入口
- 分组式疗程管理
- 权限异常前置提醒
- 温和、可信、低负担的视觉语气

### 8.2 不建议直接照搬

- 过多泛健康模块
- 与我们核心价值关系较弱的扩展工具
- 过早加入聊天助手
- 过早加入多护理对象体系
- 过早接入复杂图表

我们的产品核心是：

- AI OCR 导入医嘱
- 自动生成服药计划
- 执行提醒
- 记录与导出

所以主界面和主路径都应该围绕这一点强化，而不是均匀分配注意力。

## 9. 对我们产品的直接启发

### 9.1 首页结构建议

建议首页按这个顺序组织：

1. 顶部标题与当天状态
2. 横向日期条
3. 下一次服药卡片
4. 今日待完成任务
5. 已完成任务折叠区
6. 低库存或副作用提醒

### 9.2 新增入口建议

相比竞品，我们应更突出 AI OCR。

新增入口建议优先级：

1. 扫描医嘱 / 处方
2. 手动添加药物
3. 添加指标
4. 添加副作用

### 9.3 导航建议

基于截图参考和我们自己的 MVP，我建议底部导航先控制在 4 个：

- 今日
- 记录 / 进展
- 我的疗程
- 设置

“支持”可以暂时并入设置，避免首版导航过宽。

### 9.4 进展页建议

首版建议比竞品更聚焦：

- 服药完成率
- 连续完成天数
- 副作用记录摘要
- 指标记录摘要

不要先做太多外围卡片。

### 9.5 我的疗程页建议

保留分组结构，但第一屏优先突出：

- 当前药物
- 今日相关药物
- 剩余库存

这样更贴近用户目标。

## 10. 推荐设计原则

后续我们参考这组截图设计自己的产品时，建议遵守以下原则：

- 主路径永远围绕“今天该做什么”
- 首屏不做复杂仪表盘
- 视觉上保持温和可信，不做冰冷医院系统
- 所有 AI 结果都必须进入确认流程
- 权限和提醒异常必须前置暴露
- 扩展功能不干扰核心用药流程

## 11. 后续可直接转化为设计任务的内容

基于本次截图分析，后续可以直接进入这些任务：

- 信息架构整理
- 底部导航方案确定
- 首页线框图
- OCR 导入与确认流程页
- 我的疗程分组页
- 进展页 MVP 结构
- 设计 token 和视觉方向定义

## 12. 结论

这组截图最有价值的不是单个页面样式，而是它背后的产品组织方式：

- 高频任务集中在“今日”
- 低频配置集中在“我的疗程”和“设置”
- 回顾和成就感集中在“进展”
- 帮助能力被单独隔离

这个结构是成熟且值得借鉴的。

对我们来说，最重要的改造方向是：

- 保留这种稳定结构
- 把“AI OCR 导入医嘱并生成计划”提升为整个产品的第一卖点和第一入口
- 让首页和新增入口都为这个核心价值服务
