## 4. 已完成的用户路径闭环

### AI / OCR 路径

1. 用户输入自然语言或模拟 OCR
2. mock AI 生成长期规则、一次性任务、直接记录建议
3. 用户确认后写入对应对象
4. 长期规则进入“我的疗程”
5. 今日任务自动生成
6. 用户执行任务
7. 记录进入进展和导出

### 手动路径

1. 用户进入“手动录入”
2. 可创建长期规则、一次性任务或直接记录
3. 长期规则进入疗程并生成今日任务
4. 一次性任务只进入今天
5. 直接记录进入进展和报告

### 执行路径

1. 今日页展示待完成任务和风险
2. 用户进入任务详情
3. 支持已完成、延后、跳过、补记
4. 所有动作写入 `Record`
5. 药物任务完成后扣减库存
6. 低库存进入风险提醒

### 管理路径

- 我的疗程：查看、暂停、启用、编辑规则
- 规则编辑：修改名称、时间、说明、状态、库存和阈值
- 账户资料：维护本地显示名称
- 通知设置：模拟通知健康状态
- 隐私与免责声明：确认 AI 和医疗边界
- 备份与同步：展示本地数据摘要、生成报告、重置演示数据
- 帮助与反馈：低频问题收口

## 6. 数据模型

核心对象：

- `Rule`：长期规则，决定未来任务生成
- `Task`：某天某时刻需要执行的任务
- `Record`：用户实际执行或补记结果
- `Inventory`：药物规则的库存和低库存阈值
- `OcrDraft`：OCR 识别后、用户确认前的中间态
- `AiSuggestion`：AI 结构化建议
- `ExportReport`：复诊导出报告

主链路：

```text
AI/OCR/手动输入 -> Rule / One-off Task / Record
Rule -> Task
Task -> Record
Record + Rule snapshot -> ExportReport
Inventory -> Risk
```

## 9. 已知限制

- 还不是 iOS/uni-app 工程，不能直接上架 App Store。
- 没有真实 AI/OCR API。
- 没有真实系统通知权限检测。
- 没有账号、云同步和图片存储。
- 导出报告当前是 JSON 摘要，正式版应补 PDF/分享文件。
- 当前本地状态写入 `data/app-state.json`，该文件已被 `.gitignore` 忽略。

## 10. 下一步建议

1. 将领域层迁移到 TypeScript。
2. 将前端升级为目标移动端技术栈，建议按现有技术方案评估 `uni-app + Vue 3 + TypeScript`。
3. 接入真实 AI/OCR API，但保持“用户确认后生效”的业务边界。
4. 接入真实本地通知能力。
5. 将导出报告从 JSON 升级为 PDF 或可分享 HTML。
