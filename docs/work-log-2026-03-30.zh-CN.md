## 历史对话中的关键结论

### 产品与原型定位

- 当前阶段是原型迭代，不是正式前端开发。
- 原型可以拆分为多个独立 HTML 页面。
- 不需要本地服务，直接交付 HTML 文件，由用户自行打开查看。
- 原型评审时，应以原始 [wireframe-prototype.html](/D:/MyTherapy/docs/wireframe-prototype.html) 的结构纪律为参考，不允许随意扩展外层入口、说明层或演示壳。

### 数据流转口径

- `AI -> 仅今天`：生成一次性任务，进入今日，不沉淀为长期规则。
- 所有任务类型统一支持：`已完成 / 延后 / 跳过 / 补记`。
- `今日沉淀`：指通过今日加号手动新增的长期规则；今日加号也可新增一次性提醒。
- `OCR -> 稍后`：返回 AI，保留草稿。

### 竞品参考口径

- 竞品可借鉴的是数据闭环与任务引擎，不是页面样式照抄。
- 项目主链固定为：`输入 -> 规则 -> 任务 -> 记录 -> 进展/导出`。
- 在此基础上补入 `Inventory` 与 `Risk Alert`，保证库存不足、提醒异常等页面内容有真实数据落点。

- 新的 `design-agent-orchestrator` 已经明确后续 agents 的使用顺序与职责边界。

### 做错或代价较高的部分

- 早期将原型直接往“高保真”方向推进时，没有先锁定视觉目标与检查标准，导致页面出现遮挡、层级过厚和按钮同权等问题。
- 一度把“入口页”做出来，偏离了用户要的“今日即首页”。
- 多次是“先改视觉再复查”，而不是“先审查后编码再复查”，迭代成本偏高。
- 原型今天页虽然多轮收敛，但检查 agent 仍未完全判定通过，说明现阶段仍有继续收敛空间。
