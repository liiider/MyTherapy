# MyTherapy 低保真原型数据流转 PRD

## 1. 文档目的

本文件用于把当前低保真原型中的页面、数据、入口、流转、落点和结束状态统一梳理清楚。

目标不是定义视觉，而是确认：

- 每个页面显示的内容来自哪里
- 每个用户动作会产生什么数据
- 数据会流向哪里
- 哪些数据会沉淀为长期规则
- 哪些数据只影响当天执行

本文件基于当前原型页面：

- 今日
- 进展
- AI
- 我的
- 我的疗程
- OCR 结果确认

## 2. 核心产品数据闭环

当前产品的主闭环调整为：

1. 用户输入数据或导入治疗信息
2. 系统生成或补充长期规则
3. 长期规则实例化为每日任务
4. 用户执行任务并产生记录
5. 记录进入进展聚合与报告导出
6. 药物库存与风险提醒形成持续干预支线

其中需要明确区分两类数据：

这条闭环对应 3 条并行但相互关联的数据链：

### 2.1 规则链

`输入/导入 -> Rule -> Task`

作用：

- 决定未来会生成什么任务
- 决定提醒何时触发
- 决定今日页显示什么

### 2.2 执行链

`Task -> Record`

作用：

- 记录用户是否执行
- 记录用户何时执行
- 记录任务是完成、延后、跳过还是补记

### 2.3 回顾链

`Record -> Progress Summary / History / Report`

作用：

- 生成完成率、连续天数、分类趋势
- 生成按日期分组的历史流水
- 生成可导出的复诊资料

### 2.4 风险链

`Rule / Task / Record / Inventory -> Risk Alert`

作用：

- 识别库存不足
- 识别连续漏做
- 识别高风险副作用未记录
- 识别提醒或权限异常

### 2.5 长期规则

会持续参与未来任务生成的数据。

来源包括：

- 用户手动创建
- OCR 导入后确认保存
- AI 对话生成后保存
- 今日页加号新增并选择长期生效

长期规则最终都沉淀到：

- 我的 -> 我的疗程

### 2.2 一次性任务

只在某一天生效，不沉淀为长期规则的数据。

来源包括：

- AI 建议中选择“仅今天”
- 今日页加号新增并选择一次性提醒

一次性任务最终进入：

- 今日页的当天任务列表

不会进入：

- 我的疗程

## 3. 核心数据对象定义

## 3.1 规则 Rule

定义未来如何生成任务。

字段建议：

- rule_id
- rule_type
- title
- subtype
- schedule
- dose_or_value
- instruction
- status
- source
- start_date
- end_date
- notes

说明：

- `rule_type` 取值包括：药物、指标、情绪、症状/副作用、自定义提醒、预约
- `schedule` 包含时间、频率、是否按需
- `status` 包含：启用中、暂停
- `source` 包含：手动创建、OCR 导入、AI 生成、今日沉淀

## 3.2 任务 Task

定义某一天、某一时刻需要执行的一项内容。

字段建议：

- task_id
- task_type
- rule_id，可为空
- title
- scheduled_at
- instruction
- status
- date
- source
- is_one_off

说明：

- 来自长期规则生成的任务，`rule_id` 必填
- 来自一次性新增的任务，`rule_id` 可为空
- Task 是执行层实体，不等于 Rule
- 同一条 Rule 可以在不同日期生成多个 Task
- `status` 包含：待完成、已完成、延后、跳过、补记
- 所有任务类型都支持：已完成、延后、跳过、补记
- `is_one_off = true` 的任务不沉淀为长期规则

## 3.3 执行记录 Record

定义用户对任务的实际执行结果。

字段建议：

- record_id
- task_id
- rule_id，可为空
- record_type
- planned_at
- actual_at
- action
- value
- note
- source_page

说明：

- `action` 包含：已完成、延后、跳过、补记
- `record_type` 与任务类型一致
- 所有进展页内容都应基于记录聚合，不直接基于规则聚合

## 3.4 库存 Inventory

定义药物规则对应的剩余库存与补货风险。

字段建议：

- inventory_id
- rule_id
- current_amount
- unit
- low_stock_threshold
- refill_remind_at
- last_updated_at

说明：

- 仅药物类 Rule 强依赖库存对象
- Inventory 不直接生成任务，但可以生成风险提醒
- 当库存低于阈值时，应进入今日页或风险聚合区

## 3.5 风险提醒 Risk Alert

定义需要被用户看见并处理的异常状态。

字段建议：

- risk_id
- risk_type
- source_type
- source_id
- severity
- title
- description
- suggested_action
- status

说明：

- `risk_type` 包含：库存不足、连续漏做、权限异常、高风险副作用未记录、OCR 低置信度
- `source_type` 可来自 Rule、Task、Record、Inventory、OCR Draft
- 风险提醒是聚合结果，不是长期规则

## 3.6 OCR 草稿 OCR Draft

定义 OCR 识别后、用户确认前的中间态数据。

字段建议：

- draft_id
- image_ref
- parsed_fields
- confidence_flags
- draft_status
- created_at

说明：

- `parsed_fields` 包含：药名、剂量、频次、疗程、时间建议、备注
- `confidence_flags` 用于标记低置信度字段
- `draft_status` 包含：待确认、已保存为规则、稍后处理
- 选择“稍后”后，返回 AI，草稿保留

## 3.7 AI 建议 AI Suggestion

定义 AI 把自然语言输入整理成可执行结构后的中间结果。

字段建议：

- suggestion_id
- input_type
- raw_input
- suggestion_items
- suggestion_status

说明：

- `input_type` 包含：文本、图片、文本+图片
- `suggestion_items` 可生成：长期规则建议、一次性任务建议、记录建议
- `suggestion_status` 包含：待确认、已保存、已转一次性任务、已放弃

## 3.8 报告导出 Export Report

定义面向复诊、分享或留档的导出结果。

字段建议：

- report_id
- report_type
- date_range
- included_sections
- generated_from
- file_ref
- created_at

说明：

- `generated_from` 基于 Record 聚合，也可附带当前 Rule 概览
- `included_sections` 可包含：用药计划、服药记录、症状记录、情绪记录、测量记录
- 导出是进展页的重要结束状态之一

## 4. 页面级数据流转

## 4.1 AI 页

### 页面定位

用户输入口，承接 OCR、自由表达、AI 结构化建议。

### 页面显示内容

- 快捷入口卡片
- 用户输入内容
- AI 回复内容
- AI 建议列表
- 发送入口

### 显示数据来源

- 快捷入口：固定配置
- 对话内容：用户输入 + AI 输出
- AI 建议：由 AI Suggestion 生成

### 入口

- 底部导航进入 AI
- 今日页加号中的扫描/新增入口可跳到 AI
- 我的疗程页新增入口可跳到 AI

### 用户动作与数据流转

#### 动作 1：扫描医嘱 / 识别药单

流转：

1. 用户上传图片
2. 生成 OCR Draft
3. 进入 OCR 结果确认页

#### 动作 2：输入自然语言

例如：

- 医生说这个补剂每天早上饭后吃一片
- 最近晚上有点恶心
- 帮我加一个今晚提醒

流转：

1. 用户提交文本或图片
2. AI 解析生成 AI Suggestion
3. 页面展示结构化建议项

#### 动作 3：点击“保存”

流转：

1. 选中的建议转为 Rule
2. Rule 写入“我的疗程”
3. Rule 参与未来任务生成
4. 后续在今日页显示为任务

#### 动作 4：点击“仅今天”

流转：

1. 选中的建议转为一次性 Task
2. Task 写入今日当天任务
3. 不生成 Rule
4. 不进入“我的疗程”

### 结束状态

- 生成长期规则，等待未来执行
- 生成一次性任务，进入今日
- 保留建议，等待用户进一步处理

## 4.2 OCR 结果确认页

### 页面定位

用户确认 OCR 草稿，把 OCR 中间态转成可信规则。

### 页面显示内容

- 原图缩略图
- 药名
- 剂量
- 频次
- 时间建议
- 备注
- 风险提示

### 显示数据来源

- 全部来自 OCR Draft

### 入口

- AI 页扫描医嘱
- AI 页识别药单
- 首次欢迎页或空状态页导入医嘱

### 用户动作与数据流转

#### 动作 1：编辑字段

流转：

1. 用户修改 OCR Draft 中的 parsed_fields
2. 页面刷新显示修改后的字段

#### 动作 2：保存

流转：

1. OCR Draft 转为一个或多个 Rule
2. Rule 写入“我的疗程”
3. source 标记为“OCR 导入”
4. 后续由 Rule 生成今日任务

#### 动作 3：稍后

流转：

1. OCR Draft 保留
2. draft_status 标记为“稍后处理”
3. 返回 AI 页

### 结束状态

- 已保存为长期规则
- 草稿保留，等待稍后继续处理

## 4.3 我的疗程页

### 页面定位

规则管理中心。

### 页面显示内容

- 各类型规则分组
- 每条规则的名称
- 时间/频率
- 当前状态
- 来源标签

### 显示数据来源

- 全部来自 Rule

### 入口

- 我的页进入
- AI 保存后可跳转进入

### 用户动作与数据流转

#### 动作 1：查看规则

流转：

1. 读取 Rule 详情
2. 展示该 Rule 的完整字段

#### 动作 2：新增规则

流转：

1. 用户手动创建 Rule
2. source 标记为“手动创建”
3. Rule 写入“我的疗程”

#### 动作 3：暂停 / 启用规则

流转：

1. 更新 Rule.status
2. 影响未来 Task 生成

#### 动作 4：今日沉淀

定义：

- 来自今日页加号新增
- 用户明确选择长期生效

流转：

1. 今日页创建 Rule
2. source 标记为“今日沉淀”
3. 写入“我的疗程”
4. 未来参与任务生成

### 结束状态

- 规则被创建
- 规则被编辑
- 规则被暂停或启用

## 4.4 今日页

### 页面定位

每日执行中心。

### 页面显示内容

- 日期上下文
- 月历入口
- 下一项任务卡片
- 今日待完成任务
- 已完成任务
- 风险提醒
- 加号新增入口

### 显示数据来源

- 日期上下文：系统日期 + 用户选择日期
- 下一项任务：当天待完成 Task 中按优先级选出的最近项
- 待完成任务：Task where date=today and status=待完成
- 已完成任务：Task 对应的 Record 已产生完成结果
- 风险提醒：规则、任务、权限、库存等异常聚合
- 药物库存提醒：来自 Inventory 与 Risk Alert 聚合结果

### 入口

- 底部导航进入今日
- OCR 保存成功后可回到今日

### 用户动作与数据流转

#### 动作 1：切换日期

流转：

1. 用户选择日期
2. 重新查询该日期的 Task 与 Record
3. 刷新页面显示

#### 动作 2：执行任务

适用于全部任务类型。

动作包括：

- 已完成
- 延后
- 跳过
- 补记

流转：

1. 用户对 Task 发起动作
2. 生成或更新 Record
3. 更新 Task.status
4. 页面刷新
5. 进展页可读取该 Record

#### 动作 3：今日页加号新增长期规则

定义：

- 通过今日页加号手动增加
- 用户选择长期生效

流转：

1. 创建 Rule
2. source 标记为“今日沉淀”
3. 写入“我的疗程”
4. 如当天立即生效，可同步生成今日 Task

#### 动作 4：今日页加号新增一次性提醒

定义：

- 通过今日页加号手动增加
- 仅当天有效

流转：

1. 创建一次性 Task
2. is_one_off = true
3. 进入今日当天任务列表
4. 不进入“我的疗程”

### 结束状态

- 任务被完成
- 任务被延后
- 任务被跳过
- 任务被补记
- 新增长期规则
- 新增一次性任务
- 展示库存不足或补货提醒

## 4.5 进展页

### 页面定位

历史结果和趋势回顾中心。

### 页面显示内容

- 完成率
- 连续天数
- 趋势图
- 分类表现
- 按日期分组的历史流水
- 导出入口

### 显示数据来源

- 全部来自 Record 聚合
- 分类表现按 record_type 聚合
- 完成率基于 Task 与 Record 的匹配结果计算
- 连续天数基于“有执行记录的连续日期”计算
- 导出内容基于 Record 聚合，并可附带 Rule 概览

### 入口

- 底部导航进入进展

### 用户动作与数据流转

#### 动作 1：切换总结 / 列表

流转：

1. 读取相同时间范围的聚合结果或明细记录
2. 切换展示方式

#### 动作 2：补录

原型和文档已确认进展支持补录。

流转：

1. 用户在历史视图选择缺失项或漏记项
2. 生成或补充 Record
3. 刷新聚合结果

#### 动作 3：导出报告

流转：

1. 用户选择时间范围与导出内容
2. 系统基于 Record 聚合生成 Export Report
3. 可附带当前 Rule 概览，形成复诊资料
4. 输出文件或分享结果

### 结束状态

- 展示聚合结果
- 展示历史列表
- 完成补录并刷新统计
- 生成导出报告

## 4.6 我的页

### 页面定位

设置和规则入口容器。

### 页面显示内容

- 个人卡片
- 我的疗程入口
- 提醒与通知
- 账号与资料
- 帮助与反馈

### 显示数据来源

- 个人卡片：用户资料
- 其他入口：导航配置 + 相关状态摘要

### 入口

- 底部导航进入我的

### 用户动作与数据流转

#### 动作 1：进入我的疗程

流转：

1. 跳转到我的疗程
2. 读取 Rule 列表

#### 动作 2：进入提醒与通知 / 账号与资料 / 帮助与反馈

流转：

1. 进入对应低频设置页
2. 这些页面不直接生成今日任务

### 结束状态

- 进入规则管理
- 进入系统设置

## 6. 当前已确认的关键产品规则

1. `AI -> 保存` 生成长期规则，进入“我的疗程”。
2. `AI -> 仅今天` 生成一次性任务，进入今日，不沉淀规则。
3. 今日页中全部任务类型都支持：已完成、延后、跳过、补记。
4. `今日沉淀` 的定义是：通过今日页加号手动增加的长期规则。
5. 今日页加号也允许创建一次性提醒。
6. `OCR -> 稍后` 的结束方式是：返回 AI，并保留 OCR 草稿。

## 7. 当前原型仍缺但后续必须补齐的数据定义

这些点尚未阻塞本 PRD，但后续开发前必须继续明确：

- Rule 的频率表达格式
- 延后动作的时间规则
- 补记时是否允许补录计划时间与实际时间
- 风险提醒的判定规则
- OCR 一次识别多条规则时的拆分结构
- AI 建议中“记录建议”和“规则建议”的区分标准

## 8. 结论

当前低保真原型的数据闭环已经调整为更稳定的 4 层结构：

1. `输入层`
AI、OCR、手动新增负责接收用户输入并生成建议或草稿。

2. `规则层`
长期规则沉淀到“我的疗程”，一次性任务不沉淀。

3. `执行层`
今日页承接由 Rule 实例化出的 Task，以及当天一次性 Task；用户动作生成 Record。

4. `回顾与风险层`
进展基于 Record 做历史、统计和导出；库存、连续漏做、权限异常等通过 Risk Alert 持续提醒。

这套结构更适合作为下一步细化页面交互、接口模型和数据库结构的基础。
